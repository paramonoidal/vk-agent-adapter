# Пользовательские сценарии

## Цитирование ответов

Действие: отправить обычное сообщение боту сначала в личном диалоге, затем в групповой беседе, а после нажать callback-кнопку.

Результат: ответ в личном диалоге приходит без цитаты; ответ в группе цитирует входящее сообщение; ответ на callback сохраняет привязку к сообщению с кнопкой.

## Совместимость с Node.js

Действие: установить VK-плагин в OpenClaw 2026.8.1 на Node.js из поддерживаемого самим OpenClaw диапазона.

Результат: установка допускается на Node.js 22.22.3–22.x, 24.15.0–24.x и 25.9.0+, а неподдерживаемые ветки отклоняются до запуска плагина.

## Обновление до OpenClaw 2026.8.2

Действие: установить `@openclaw-vk/vk@2026.8.31`, перезапустить gateway и выполнить `openclaw channels status --probe`.

Результат: VK-плагин загружается без ошибок SDK, канал работает в режиме Long Poll, probe возвращает `works`.

## Длительная работа Long Poll

Действие: оставить подключённый VK-канал без входящих сообщений более чем на 30 минут.

Результат: успешные пустые Long Poll-ответы обновляют транспортную активность; gateway не считает канал зависшим и не запускает цикл перезапусков.

## Зависший Long Poll

Действие: после хотя бы одного успешного опроса транспорт перестаёт завершать Long Poll-запросы дольше `channels.vk.transport.silenceMs`.

Результат: задача аккаунта завершается, а единственным владельцем повторного запуска остаётся штатный lifecycle OpenClaw.

## Диагностика без утечки данных

Действие: включить `channels.vk.diagnostics.level: "redacted"`, вызвать ошибку доставки и проверить журнал gateway.

Результат: журнал содержит этап, вид вложения и безопасный код ошибки, но не содержит токен, подписанный URL, путь, имя собеседника или содержимое вложения; account-level `diagnostics` отклоняется валидатором.

## Doctor в OpenClaw 2026.9.5

Действие: установить плагин, выполнить `openclaw doctor --fix`, затем проверить `openclaw status`.

Результат: VK-плагин явно сообщает пустой контракт собственных state-миграций и не удерживает gateway в состоянии ожидающей миграции.

## Личное сообщение и ответ

Действие: разрешённый пользователь отправляет боту личное сообщение, агент отвечает текстом.

Результат: входящее сообщение попадает правильному агенту, ответ доставляется в тот же VK-диалог.

## Pairing нового пользователя

Действие: новый пользователь пишет боту при `dmPolicy: "pairing"`, затем оператор подтверждает полученный код.

Результат: доступ открывается только подтверждённому пользователю и только для исходного `accountId`.

## Несколько VK-сообществ

Действие: запросить и подтвердить pairing отдельно в двух именованных VK-аккаунтах.

Результат: подтверждение в одном сообществе не открывает доступ во втором.

## Входящие вложения

Действие: отправить одним сообщением изображение и документ.

Результат: агент получает оба вложения в исходном порядке с корректными типами и локально материализованными файлами.
